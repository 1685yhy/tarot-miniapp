## 一、星光手账（心情日历 · 情绪可视化+月度复盘）

### 1.1 用户流程（4 步）

1. **入口**：首页今日星光卡下方"foot-entry 区"新增「星光手账」（与"记录今天"合并，见 1.5 关系决策）；我的页亦可进入 → `pages/journal/journal`
2. **点亮星点**：手账页顶部"今晚，记一颗星"——5 档星光亮度横向选择（满溢/明亮/常亮/微暗/隐没），一键记录；月历上当天立即亮起一颗星
3. **深化记录（可选）**：点击月历上任一天 → 星点详情展开：情绪档 + 当日卡牌 + 可选文字（复用日记 reflection 输入，可 AI 反思提问）→ "让这一天更亮一点"（可改情绪档）
4. **月度复盘**：月历顶部"本月星光回顾"卡 → `pages/journal-review/journal-review`：情绪曲线 + 亮暗星统计 + AI 月度温柔总结 + 星光色统计 → 保存/分享星光手账海报

### 1.2 交互与视觉要点（E3 星光叙事，不写死样式）

- **星点=情绪，星光色=当日星光**：月历每天一颗星点，颜色取当日 `build_today_guidance` 星光色（12 色暖金系天然和谐），亮度/光晕大小映射情绪档（5 档）。夜空中既有色彩层次，又有明暗故事
- **五档亮度命名**：满溢星光 / 明亮星光 / 常亮星光 / 微暗星光 / 隐没星光（对应情绪 excited/happy/calm/thoughtful/anxious+sad）。暗星不禁忌——"隐没的星也在夜空里"，低落被看见、不评判
- **月历手势**：左右滑切月；今天高亮环；未记录日显示极淡星尘点（"留一颗星的位子"空态引导）
- **记录摩擦**：5 档亮度一屏选择、点按即存，3 秒完成；完成 toast"今晚的星，已挂上夜空 ✦"
- **月度复盘叙事**：以"夜空被点亮了多少"为主线（点亮天数/亮暗比例），AI 文案温柔克制；星光色统计用色点串成"本月星空色带"
- 空月/首月引导：全月零记录时给一句"夜空从不催促，星会等你" + 引导今日点星

### 1.3 数据模型 + 接口草案

**决策：不新建心情表，复用 diary_entries（合并关系见 1.5）。** 新增 1 张复盘缓存表。

```sql
-- 新增表 1：月度星光复盘缓存（仿 moon_reviews 模式：每人每月一份，避免重复 AI 调用）
CREATE TABLE star_monthly_reviews (
    id          CHAR(36) PRIMARY KEY,
    user_id     CHAR(36) NOT NULL INDEX,
    month       CHAR(7)  NOT NULL,              -- '2026-08'
    data        TEXT     NOT NULL,              -- 复盘 JSON（review/insight/tips/stats）
    created_at  DATETIME, updated_at DATETIME,
    UNIQUE KEY uq_user_month (user_id, month)
);

-- 复用表：diary_entries（mood 枚举沿用现有 6 档）
--   excited/happy/calm/thoughtful/anxious/sad
--   → 星光亮度映射（代码常量，不落库）：
--     excited=5(满溢) happy=4(明亮) calm=3(常亮) thoughtful=2(微暗) anxious|sad=1(隐没)
```

| 接口 | 方法 | 说明 |
|---|---|---|
| `/journal/calendar?year=&month=` | GET | 月历数据：每日 `{date, mood, brightness(1-5), star_color, has_reflection, card_id}`（star_color 由 `build_today_guidance` 按日确定性生成，不存储）+ 月度统计 `{days_recorded, bright_count, dim_count, current_streak}` |
| `/journal/entries` | POST | 记录/更新今日星点（内部复用 diary 服务；mood 必填、reflection/card_id 可选）。写成功时检测"连续 7 天记录"→ 星尘 +1（幂等，同周不重复） |
| `/journal/review?month=2026-08` | GET | 月度星光复盘（缓存命中即返回；无缓存时聚合当月日记+卡牌+天象→AI 生成并缓存）。非会员计入 `diary_ai_count_today` 配额（与周回顾共享 FREE_DIARY_AI_DAILY） |
| `/journal/review/regenerate` | POST | 手动重生成（覆盖当月缓存，会员/付费可用，防滥用限流） |
| `/journal/review/share-preview?month=` | GET | 海报数据（脱敏：情绪档位统计+AI 摘要+星光色带，无昵称无原文） |

月度复盘 AI 输入：当月全部日记（mood 标签 + reflection 摘要片段）、当月出现最多的卡牌、当月新/满月天象。输出 JSON：`{trend_summary 一句话情绪趋势, insight 洞察, next_guide 下月行动, bright/dim 统计口径}`。AI 失败降级本地温柔模板（复用满月复盘 `_FALLBACK_*` 模式）。红线复用 `_AI_RED_LINE`（不预测/不恐吓/日记感知不引用）。

### 1.4 星光叙事包装

- 功能名：**星光手账**；月历即"我的星光夜空"
- 记录动作：**"点亮今晚的星" / "记一颗星"**
- 五档命名：满溢星光 ✦✦✦✦✦ / 明亮星光 ✦✦✦✦ / 常亮星光 ✦✦✦ / 微暗星光 ✦✦ / 隐没星光 ✦
- 文案示例：
  - 记录成功："今晚的星，已挂上夜空 ✦"
  - 低落日不评判："隐没的星，也是夜空的居民。它只是需要一点时间，再亮起来。"
  - 月度复盘开场："你的八月，是一整片被点亮的夜空——21 颗星里，15 颗亮着，3 颗正在休息。"
  - 连续 7 天："七夜连星，你为自己点亮了一条银河（+1 星尘）"
- 合规：复盘绝不下"你越来越糟/越来越好"的定性结论，只描述夜空状态

### 1.5 与现有功能复用点（明确列）

1. **diary_entries 表**：唯一情绪数据源，6 档 mood 复用，不建新表
2. **AI 周回顾引擎**（`/diary/review` 已支持 `period=monthly`）：月度复盘直接复用其 prompt 模式与配额逻辑
3. **moon_reviews 缓存模式**：按人按周期缓存 AI 结果，避免重复调用
4. **build_today_guidance**：每日星光色确定性生成（月历着色免存储）
5. **卡牌体系**：星点详情关联当日 tarot_cards（pick_daily_card）
6. **canvas-poster/share-poster**：月度手账海报
7. **星尘/星阶**：7 天连续记录奖励 +1 星尘（第二个星尘来源）
8. **今日星光卡首页**：入口 + 星点记录后首页星光卡文案微联动（"今晚的星已点亮"角标，可选）

**与情感日记的关系决策（建议合并）**：星光手账是情感日记的"星光视图升级"——原 `pages/diary/` 文字日记页改为手账样式（月历为壳、星点为快记、点开可写文字），避免"日记"与"手账"双入口双数据源。原日记列表/删除/图片上传能力保留在手账详情展开中；旧页面路径保留跳转兼容。

### 1.6 实施切分建议（5 个任务，约 5 人日）

1. **T1-1 后端**：亮度映射常量 + `/journal/calendar` 月历聚合（TDD：确定性、空月、跨月）——1 日
2. **T1-2 后端**：`star_monthly_reviews` 表 + `/journal/review` 月度复盘（复用 diary AI，降级模板）——1 日
3. **T1-3 后端**：`/journal/entries` + 连续 7 天星尘奖励（幂等）——0.5 日
4. **T1-4 前端**：手账页（月历+五档点星+星点详情）、旧日记页跳转改造——1.5 日
5. **T1-5 前端**：月度复盘页 + 手账海报（复用 canvas-poster）+ 首页入口——1 日

### 1.7 风险

- **双入口困惑**：日记/手账并存 → 已设计合并（旧页跳转）
- **AI 成本**：月度复盘与周回顾共享每日配额，缓存+降级模板兜底

## 二、星辰相遇（双人合盘 · 社交裂变）

### 2.1 用户流程（快速版 4 步 / 邀请版 6 步）

**快速版（主力，零门槛）**
1. 首页/我的 → 「星辰相遇」入口 → `pages/meet/meet`
2. 选择关系（朋友/恋人/家人/同事）+ 对方星座（12 宫格选择）；可选补充对方出生日期/时间（提升精确度）
3. 生成结果页：星辰共鸣度（档位）+ 三要素分解（太阳/月亮/上升各自相容度）+ 合盘三牌阵 + 相处提示
4. 分享合盘海报（保存图片/转发好友）→ 好友扫码落 `meet-landing`

**邀请版（裂变引擎）**
1. 发起人在结果页点「邀请 ta 相遇」→ 生成相遇邀请（小程序码 scene=`m:{meet_id}` / 分享卡片）
2. 好友扫码 → `pages/meet-landing/meet-landing`（公开页：发起人昵称+星座+星阶，脱敏）
3. 好友填自己的星座或出生信息（微信授权昵称可选）
4. 系统合盘 → 双方都能在各自端查看完整结果
5. 结果页 → 继续分享 / 接受方完成可触发邀请奖励（复用 `/share/invite` 免费解读机制，见 6.4）
6. 分享闭环：合盘海报再次带小程序码，海报即拉新入口

### 2.2 交互与视觉要点

- **输入即仪式**：星座选择用 12 宫格（每格一个星座符号+元素底色）；关系选择用 4 枚星光徽章（友/恋/亲/事）
- **结果页结构（自上而下）**：双星徽章并置（两枚星光徽章+名字）→ 共鸣度大圆环（百分值+档位名）→ 三要素分解卡（太阳/月亮/上升 各自相容度条+一句话原因，可展开"为什么"）→ 三牌横排（牌图+牌名+一句）→ 相处提示卡 →「仅供娱乐 · 星光映照」固定尾行
- **确定性承诺**：同两人任何时候算结果一致（与能量引擎同哲学："准"=可解释可验证）；每项分数旁给原因（"同元素·火象相映 +8"）
- **海报版式**：复用 E3 星光名片身份卡样式——双人徽章、共鸣度、三牌、小程序码；底部「仅供娱乐」小字；海报过内容安全检测（msg_check）
- 空态：好友信息不足时（只有星座）结果页明确标注"月亮落座未知，共鸣度按太阳星座估算"，引导补全

### 2.3 合相算法（简单确定性：三要素加权）

**输入**：太阳星座（双方必有）；月亮落座（有出生日期可算，复用 `birthchart.moon_sign`）；上升（有出生时间+城市可算，复用 `birthchart.rising_sign`）

**权重**：总分 = 太阳 50% + 月亮 30% + 上升 20%。缺要素时权重重归一化（如仅太阳 → 100% 太阳；无上升 → 太阳 62.5% + 月亮 37.5%）

**星座兼容表（12×12）**：由元素规则生成初稿 + 人工抽查定稿：
- 同元素（火/土/风/水四组）→ 85-95 分；互补元素（火风、土水）→ 75-85 分；其余组合按固定表 55-75 分
- 同模式（基本/固定/变动）微调 ±3；整表存代码常量，可运营调整（同 STAR_COLORS 的治理方式）
- 月亮落座与上升各自用同一张兼容表

**档位**：85+ 星光共鸣 / 70-84 星光相映 / 55-69 星光相伴 / <55 星光初见

**合盘牌阵（确定性 3 张）**：seed = 双方出生日期拼接 + 日期（与 pick_daily_card 同哲学，同日同人恒定）：
1. 关系之牌：这段关系像什么（`meaning_upright` 截取+模板包装）
2. 星光之牌：对方眼中的你
3. 相处之牌：相处时的星光提示（此牌文案走"相处提示"合规框架）

**相处提示（合规关键）**：全部由模板+牌意生成，开放积极向：
- "你们的星光节奏是**慢热**的——先并肩走一段，再慢慢看清彼此的方向。"
- 禁"注定/天生一对/该在一起/分开/克"类措辞；结果页固定行：「星辰只描述你们如何相处，不定义任何结局 · 仅供娱乐」

### 2.4 数据模型 + 接口草案

```sql

    b_moon         VARCHAR(16) NULL, b_rising   VARCHAR(16) NULL,
    status         VARCHAR(16) NOT NULL DEFAULT 'completed',  -- pending|completed

```

安全：出生信息按 api_security_redline 加密存储策略（birth 字段与 users.birth_* 同待遇）；meet 公开接口只出海报字段；内容安全检测覆盖海报文案。

### 2.5 星光叙事包装

- 功能名：**星辰相遇**；核心指标：**星辰共鸣度**（不是"缘分度/契合度"——共鸣是相处的可能性，不是命运的判决）
- 档位命名：星光共鸣 / 星光相映 / 星光相伴 / 星光初见
- 三牌命名：关系之牌 / 星光之牌（对方眼中的你）/ 相处之牌
- 文案示例：
  - "双鱼与巨蟹的星光，彼此借光。月亮落在同一片海域，情绪不用翻译。"
  - "天蝎与白羊，一颗在深水里，一颗在火焰里——你们需要给星光留一点呼吸的空间。"
  - 分享文案："我和 TA 的星辰共鸣度是 92 · 看看你和谁星光相映 ✦"
- 合规：全部输出走"相处方式描述"框架，永不输出"合适/不合适/注定"定性

### 2.6 与现有功能复用点

1. **`/share/zodiac-match`（v1.5 已有）**：它的"星座+塔罗关系牌+AI 文案"是快速版雏形——P1 升级为确定性三要素算法，原接口保留兼容
2. **birthchart 三要素引擎**：`sun_sign/moon_sign/rising_sign` 直接复用（好友出生信息同样算出三要素再合盘）
3. **wxacode+落地页模式**：`/share/wxacode` + `card-landing` 的模式复制到 meet 邀请（scene=`m:{id}`）
4. **share/invite 奖励体系**：好友扫码注册加入 → 触发 `process_invite`（双方各 +1 免费解读）
5. **share-poster/canvas-poster**：海报渲染管线复用
6. **E3 星光名片样式**：双人徽章版式（星阶徽章/星光色边框）

### 2.7 实施切分建议（6 个任务，约 6 人日）

## 四、睡前星语（21:00 短句 + 月光卡）

### 4.1 用户流程（4 步）

1. **选择时段**：订阅引导升级为"二选一"——晨讯（7:37 今日星光）或星语（21:00 睡前一句）；默认晨讯，可随时在"我的-推送设置"切换
2. **收到星语**：21:00 订阅消息：一句晚安短句（结合当日星光）+ 今日星光数/星光色 → 点击进入月光卡
3. **月光卡**：`pages/moon-card/moon-card`：当夜月相大图 + 星语 + 星光色 + 小程序码 → 可保存/分享（晚安卡）
4. **沉淀**：月光卡文案结尾引导"睡前三分钟，给今天记一颗星"（跳手账）；分享月光卡 = 拉新入口（小程序码）

### 4.2 交互与视觉要点

- **额度语义**："你订阅的，是每晚一颗属于你的星"——晨讯/星语二选一是"选择星光降临的时刻"，不是"取舍"话术
- 星语内容：短句 ≤20 字（thing1 限制），结合当日能量维度（今日能量最高的维度对应文案池）与星光数/星光色
- **月光卡版式**：E3 名片同系——深空底 + 当夜月相 + 一句星语 + 日期 + 星光色描边 + 小程序码 + 「仅供娱乐」小字；是"晚安版星光名片"
- 收到推送后小程序内红点/角标引导打开月光卡（订阅消息点击直达）
- 切换时段交互：设置页两枚星光按钮（晨星/晚星）高亮所选；切换次日生效

### 4.3 额度分配规则（与晨讯共享 1 条/天）

**设计决策：槽位偏好 + 时间槽 + 原子认领三重约束，天然保证"全局每日 1 条"。**

- `SubscribeQuota` 增加 `slot_preference` 列（`morning` 默认 / `night`），即"用户选择的星光时刻"
- 7:37 晨讯只扫描 `slot_preference='morning'` 且有额度用户；21:00 星语只扫描 `'night'` 用户
- 两槽位**共用同一个原子认领**（`UPDATE last_sent_date=today` rowcount==1 才发）+ 共用 `quota_available` 消费（成功 -1）→ 即使并发交错，同用户同日也最多发 1 条
- 结果语义：
  - 用户默认晨讯 → 7:37 收今日星光，晚上不打扰
  - 用户切夜星 → 7:37 不发，21:00 收睡前星语（晨讯额度"让渡"给星语）
  - 用户没额度 → 两槽位都不发（授权即额度，1 授权 = 1 条，机制不变）
- **存量迁移**：现有 21:00"今晚之牌"推送（按订阅列表、不消费额度）升级为额度制星语——行为变化是"未再授权的老用户晚间不再推送"。迁移策略：老用户保留 TEMPLATE_DAILY_CARD 订阅记录作为"推送开关"展示；设置页文案引导重新授权一次（微信一次性订阅的固有机制，无法自动续）。需在发布说明中告知
- 月相事件优先保留：新月前 1 天/满月当天的 21:00 节点推送仍优先生效（节点召回不因槽位偏好丢失——节点推送发给全部有额度用户，仍守每日 1 条）

### 4.4 数据模型 + 接口草案

```sql

-- 不新增内容表：星语短句库为代码常量（50 条 × 4 维度池），确定性选择
```

## 五、四功能关联设计：一个体系的四个齿轮

**1. 星尘经济闭环（手账×日历×相遇→星阶→名片）**
签到 +1 / 手账连续 7 天 +1 / 节点打卡 +1 → `stardust_total` → 星阶（微光→星光→星辉→星冠）→ 名片与海报上的星阶徽章更亮 → 分享意愿更强 → 拉新。星尘来源从 1 个扩到 3 个，"越用越亮"的成长线贯穿全部新功能。

**2. 推送体系闭环（晨讯×星语×节点）**
1 条/天额度 + 槽位偏好（晨星/晚星）+ 节点日内容切换 → 用户在"低打扰"前提下，每天收到的是"星光时刻"而不是"三条消息"。节点活动（新月/满月/水逆）通过内容切换自然进入每日一条的召回管道——这就是"订阅消息最佳召回场景"的实现：不新增打扰，只让该来的那条更有意义。

**3. 分享裂变闭环（名片→合盘→月光卡→手账）**
四种海报全部带小程序码（scene 区分：名片=`invite_code`、相遇=`m:{meet_id}`、月光卡=名片码、手账海报=名片码）→ 扫码落地（card-landing/meet-landing 公开页）→ 新用户注册 → `/share/invite` 双向奖励（+1 免费解读）→ 新用户继续分享。合盘海报自带社交话题（"我和 TA 的共鸣度"），是四张海报中裂变系数最高的——P1 主推。

**4. 情感主线闭环（星语→手账→复盘）**
星语每晚引导"给今天记一颗星"→ 手账记录率提升 → 月度复盘有料 → 复盘 AI 与满月复盘互相引用（复盘里提一句"这个月你点亮了 N 颗星"）→ 手账成为情感留存主轴（情感类留存 45%）。

**5. 合规统一框架**
所有新结果页/海报固定「仅供娱乐 · 星光映照」；AI 文案全部走 `_AI_RED_LINE`（不预测/不恐吓/不命运定性）；海报文案过 msg_check；措辞白名单测试（合盘档位名/宜忌库/星语库入库校验，仿 STAR_GUIDANCE_LIBRARY 测试）。

**6. 入口统一**
首页今日星光卡成为"星光宇宙中枢"：星光卡（能量+宜忌）→ 星象宜忌跳日历；foot-entry 区新增 手账/相遇/星空时刻表 三个入口（现有 记录今天/星光树洞 重组）；我的页星阶区展示 手账连续记录 + 节点完成 + 推送偏好。
