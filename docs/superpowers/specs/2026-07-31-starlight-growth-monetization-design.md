# 星光映照 · 增长&变现路线设计

**生成时间**: 2026-07-31
**设计类型**: 三阶段增长+变现路线图
**前置文档**: [精品上线设计](./2026-07-26-starlight-launch-design.md) / [Design Council PRD](../../DESIGN-COUNCIL-PRD.md)
**目标用户**: 都市女性 22-35（主攻）+ 女大学生 18-22（兼收）
**产品定位**: AI塔罗陪伴空间，镜子不是预言

---

## 总览

三阶段、三线并行。内容引擎拉新、裂变机制放大、产品品质留住。

```
           P0 审核上线        P1 获客增长        P2 转化变现
           目标2-3周          目标3-4周          目标2-3周

内容引擎    ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━▶
           框架搭建              持续产出             UGC闭环

裂变增长            ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━▶
                    分享卡片+邀请          社群+话题裂变

产品体验    ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━▶
           审核打磨              体验优化             付费后移
```

**原则**: 品质是底线，获客是引擎，变现是自然而然的延伸——不是目的。

## P1 — 获客增长（目标 3-4 周）

**一句话**: 内容引擎全速运转，裂变工具上线，用户开始进来。

### 1.1 内容引擎（A线主力）

| # | 事项 | 说明 |
|---|------|------|
| 1.1.1 | 公众号稳定运营 | 周更2-3篇，固定栏目："星光周运"（周一）、"牌面故事"（周三/四）、"树洞精选"（周末） |
| 1.1.2 | 小红书同步分发 | 每篇公众号内容适配小红书图文格式（标题党化但不low、emoji点缀、卡片式排版） |
| 1.1.3 | 视频号试跑 | 每日一牌短视频（15-30秒）：卡牌图像展示 + AI配音解读 + 日期 + "打开小程序抽你的今日牌" |
| 1.1.4 | 内容→小程序埋点 | 所有内容底部统一挂小程序入口卡片，带UTM参数追踪各渠道转化 |
| 1.1.5 | 第一批种子话题 | 小红书："塔罗真的准吗""AI塔罗vs真人塔罗""我的每日一牌日记"等天然高互动话题 |

### 1.2 裂变增长（B线主力）

| # | 事项 | 说明 |
|---|------|------|
| 1.2.1 | 分享卡片正式上线 | 解读完成页底部"保存分享图"按钮，点击生成图片→保存相册→自然分享 |
| 1.2.2 | 好友送牌 | 用户A邀请用户B → B通过小程序码进入 → 双方各得一次免费深度解读（非会员也可以） |
| 1.2.3 | 星座契合度 | 两人选星座 → 生成一张"你们的关系牌"分享图（社交货币型内容） |
| 1.2.4 | 每日一牌打卡图 | 抽完每日牌→一张带卡牌+日期+"连续N天"的打卡图→朋友圈/微信群自然传播 |
| 1.2.5 | 避免触碰红线 | 不做"转发到3个群解锁"、不做强制分享、不做虚假诱导——微信封号风险 |

### 1.3 产品体验（持续打磨）

| # | 事项 | 来源 | 说明 |
|---|------|------|------|
| 1.3.1 | 卡片系统精简 | Design Council 5.5 | 7种卡片变体→3种（default/interactive/featured） |
| 1.3.2 | 首页入口精简 | Design Council 4.1 | 11个可交互入口→5个核心 |
| 1.3.3 | 解读页重排 | Design Council 4.2 | 角色标识→解读文本→行动建议→（可折叠）深度内容→分享/保存/日记 |
| 1.3.4 | streak+collection移到profile | Design Council 4.1 P2 | 卡面不再显示这些数据 |
| 1.3.5 | 星场粒子减半 | Design Council 5.4 | 视觉效果减弱50%，性能提升 |
| 1.3.6 | 移除视差星空漂移 | Design Council 5.4 | 静态星空即可，减少GPU开销 |
| 1.3.7 | 图片转WebP 240px | Design Council 8.3 | 减少图片资源体积 |

### 1.4 数据分析基础

| # | 事项 | 说明 |
|---|------|------|
| 1.4.1 | 关键埋点 | DAU/新增用户/来源渠道/每日抽牌率/解读完成率 |
| 1.4.2 | 分享链路追踪 | 分享图生成→分享→扫码进入→完成首次解读 |
| 1.4.3 | 内容渠道追踪 | 公众号/小红书/视频号/微信群 各渠道来源用户数和留存 |
| 1.4.4 | 周数据看板 | PM可每周看：新用户数、来源占比、次日/7日留存、付费转化 |

**P1 验证门**: DAU稳定增长 + 分享链路跑通 + 内容周更不断档 + 留存数据有基线

## P2 — 转化变现（目标 2-3 周）

**一句话**: 读完之后才谈钱。所有付费入口在体验之后。

### 2.1 付费体验重构（Design Council 3.4 精神）

| # | 事项 | 当前问题 | 目标 |
|---|------|----------|------|
| 2.1.1 | 所有付费CTA后移 | 会员入口散布在首页、解读中、聊天中 | 只在"解读完成后"出现一次付费提示 |
| 2.1.2 | 免费试用延长 | 3天试用 | 改为7天试用（更长的信任建立期，竞品测测也是7天） |
| 2.1.3 | 每日免费额度保持 | 5次/天 | 保持5次（不压榨免费用户来逼付费） |
| 2.1.4 | 会员页精简 | 包含"星光好物"临时电商板块 | 移除未上线的电商板块，专注会员价值 |
| 2.1.5 | 首次付费时机 | 9.9元CTA在首页展示 | 改为：用户完成第一次解读后，才出现"9.9元解锁深度版" |
| 2.1.6 | 聊天页付费移除 | 聊天底部有会员提示 | 只在用户额度真正耗尽时，出现一行文字链接 |

### 2.2 变现数据驱动

| # | 事项 | 说明 |
|---|------|------|
| 2.2.1 | 付费漏斗埋点 | 免费使用→试用→付费，每一步转化率 |
| 2.2.2 | 流失节点分析 | 用户在哪个页面/哪个时机离开？ |
| 2.2.3 | 价格敏感度测试 | A/B测：9.9元 vs 19.9元 首次深度解读，看转化率差异 |
| 2.2.4 | 付费用户画像 | 付费用户vs免费用户的留存/使用频率差异 |
| 2.2.5 | 分享→付费链路 | 被邀请用户的付费转化率 vs 自然用户的付费转化率 |

### 2.3 内容闭环升级

| # | 事项 | 说明 |
|---|------|------|
| 2.3.1 | UGC分享卡片 | 用户日记精选（匿名）自动生成分享卡片 → 内容引擎的新燃料 |
| 2.3.2 | AI周报分享 | "本周你的情绪旅程"精美长图 → 天然分享素材 |
| 2.3.3 | 树洞话题运营 | 每周一个匿名话题（"你最想对前任说什么""今年你做过最勇敢的事"） → 社群讨论 → 精选到公众号 |

**P2 验证门**: 付费转化率有基线数据 + 付费流程无体验断点 + 内容闭环初步运转

## 关键原则（红线）

| 不做 | 为什么 |
|------|--------|
| 微信广告投放（早期） | 成本高、ROI低、品牌调性不符——等数据跑通再评估 |
| 诱导分享（"转发到N个群解锁"） | 微信审核红线，封号风险 |
| 付费弹窗打断解读 | 破坏情感体验，Design Council明令禁止 |
| 压缩免费额度逼付费 | 杀鸡取卵——竞品"测测"正因诱导消费而流失口碑 |
| 付费入口超过1个/页 | "当一个页面出现两个付费入口，用户就开始数你的变现手段而不是感受产品"（Jony Ive, PRD附录A） |
| 假数据/假用户/虚假繁荣 | 增长的数据必须真实，PM需要对真实情况有判断 |

## 不做的事（明确排除）

- 公众号日更（质量>数量，周更2-3篇是上限）
- 社群强运营（当前没有运营人力，靠自然+内容）
- 实体周边电商（"星光好物"暂时移除）
- 付费广告投放（P2以后根据ROI数据再评估）
- Android/iOS独立App（微信小程序足够）

## 与 Design Council PRD 的关系

本路线图**完全遵循** Design Council PRD (2026-07-30) 的核心原则和Phase A-D框架，差异在于：

- PRD的Phase A（快速见效）→ 本路线图融入P0和P1，优先做
- PRD的Phase B（信息架构大修）→ 本路线图融入P1产品体验打磨
- PRD的Phase C（变现克制）→ 本路线图P2，完全采纳
- PRD的Phase D（无障碍+性能）→ 本路线图分散到各阶段的体验任务中

**新增加的内容**（PRD未覆盖）：内容引擎搭建（公众号/小红书/视频号）、裂变分享机制、友邀体系、数据埋点和追踪——这些是PRD聚焦"产品设计"时未涉及的"增长运营"维度。

## 附录：内容栏目规划

### 公众号固定栏目

| 栏目 | 频率 | 内容方向 | 目标 |
|------|------|----------|------|
| 星光周运 | 每周一 | 十二星座本周塔罗指引 | 固定回访理由 |
| 牌面故事 | 每周三/四 | 一张牌的深度故事（神话/历史/现代生活关联） | 展示知识厚度 |
| 树洞精选 | 每周六/日 | 匿名用户日记/投稿精选（获授权） | UGC激励+情感共鸣 |
| 星光对话 | 不定期 | 产品更新/新功能/活动通知 | 产品和用户之间的桥梁 |

### 小红书内容方向

| 类型 | 示例标题 | 目标 |
|------|----------|------|
| 知识型 | "塔罗牌0号·愚人：为什么最厉害的牌是'什么都不知道'" | 展示专业性，吸引对塔罗有兴趣的用户 |
| 共鸣型 | "抽到死神牌别怕，这恰恰说明你准备好了" | 情感共鸣，转发收藏 |
| 互动型 | "截屏看你今天抽到什么牌 | 塔罗每日一牌" | 互动率，算法推荐 |
| 日常型 | "我用AI塔罗做了一年的日记，发现的3个规律" | 信任感，产品植入 |
